## 2. 硬件接口

### 2.1 连接表

| W5500 模块 | STM32F407 | 说明 |
|---|---|---|
| 3.3V | 3.3V | 与 5V 引脚**二选一**，不可同时接 |
| **GND** | **GND** | ★ **必须与核心板共地**，见 10.1 |
| SCLK | **PB10** | SPI2_SCK，复用 AF5 |
| MISO | **PC2** | SPI2_MISO，复用 AF5 |
| MOSI | **PC3** | SPI2_MOSI，复用 AF5 |
| SCS | **PE13** | GPIO 推挽输出，空闲高电平 |
| RST | 未接 | 模块自带 10k 上拉；用软件复位代替 |
| INT | 未接 | 驱动采用轮询，不使用中断 |
| NC | 悬空 | — |

### 2.2 引脚选择依据

| 决策 | 理由 |
|---|---|
| SPI2 用 PB10/PC2/PC3，而非默认 PB13/14/15 | F4 的复用功能是**逐脚选择**的（不像 F1 整组重映射），两组都合法；选这组是为了把 PB13~15 留给后续外设 |
| SCS 必须用 GPIO 软件控制 | SPI2 的硬件 NSS 是 PB12，已被 `TFT_CS` 占用；且硬件 NSS 只在单次 HAL 调用内有效，无法包住「帧头+数据」整帧（见 3.3） |
| RST 不接 | 用 `MR = 0x80` 软件复位代替，效果等同断电重启（见 8.1） |
| INT 不接 | 数据量小，50ms 轮询 `Sn_SR` 足够；省去 EXTI 与中断上下文的复杂度 |

### 2.3 供电注意事项

- 模块板载 LDO：5V 输入 → 3.3V 输出。**若把 3.3V 接到模块的 5V 脚，LDO 压差不足，输出只有 2.x V**，
  W5500 供电不足不工作，但电源灯照样亮——极易误判。
- 本工程直接把核心板 3.3V 接到模块 **3.3V 脚**（LDO 输出兼输入），实测正常。
- 典型工作电流 128mA，注意与其它外设的电源预算。

## 3. 模块特性

### 3.1 硬件 TCP/IP

W5500 内部实现 ARP / IP / ICMP / TCP / UDP / PPPoE 等协议，并提供 **8 个独立硬件 Socket**，
每个 Socket 默认 2KB 收发缓存（共 16KB + 16KB）。

**这意味着：ARP 应答、ICMP ping、TCP 三次握手、重传与超时全部由芯片完成**，
MCU 只需通过 SPI 读写寄存器和缓冲区。

### 3.2 型号说明：BSB 布局与数据手册不一致（★）

| 区域 | W5500 数据手册 | **本模块实测** |
|---|---|---|
| 通用寄存器 | `0x00` | `0x00` |
| socket n 寄存器 | `0x01 + n` | **`4n + 1`** |
| socket n 发送缓存 | `0x09 + n` | **`4n + 2`** |
| socket n 接收缓存 | `0x11 + n` | **`4n + 3`** |

模块 `VERSIONR` 返回 `0x04`（W5500 的 ID），但地址布局沿用旧架构，大概率为兼容芯片。
**不影响使用，但不能照 W5500 数据手册直接写缓冲访问。**

```c
#define W5500_BSB_COMMON    0x00
#define W5500_BSB_SREG(n)   (0x01 + 4 * (n))
#define W5500_BSB_TXBUF(n)  (0x02 + 4 * (n))
#define W5500_BSB_RXBUF(n)  (0x03 + 4 * (n))
```

> **换正品 WIZnet 模块时，后三行必须改回 `(0x01+n)` / `(0x09+n)` / `(0x11+n)`。**
> 判断方法见 10.3。

## 4. SPI 传输层

### 4.1 参数

| 项 | 值 | 理由 |
|---|---|---|
| Mode | Full-Duplex Master | W5500 有独立 MOSI/MISO：帧头往 MOSI 发、数据从 MISO 收 |
| Frame Format | Motorola | 标准 CPOL/CPHA 四选一 |
| Data Size | 8 Bits | 地址、控制、数据均为 8 位 |
| First Bit | MSB First | W5500 规定高位先出 |
| Hardware NSS | Disable | 片选用 GPIO（见 2.2） |
| CPOL / CPHA | Low / 1 Edge | **Mode 0**（W5500 支持 Mode 0 与 Mode 3） |
| CRC | Disabled | W5500 不使用 SPI CRC |
| Prescaler | **/16** | SPI2 挂 APB1 = 42MHz，42/16 = **2.625 MHz** |

**时钟链**：`HCLK 168MHz → APB1 分频 4 = 42MHz → SPI2 分频 16 = 2.625MHz`。

可选档位只有 /2(21M)、/4(10.5M)、/8(5.25M)、/16(2.625M)、/32(1.31M)。
本项目**锁定 /16**：数据量只有几十字节，2.625MHz 下有充足余量；21MHz 对面包板 + 20cm 杜邦线偏激进。

> CubeMX 生成的 `spi.c` 里默认是 `/2 = 21MHz`，由 `W5500_Init()` 覆盖为 `/16`。
> **以 `W5500.c` 中的设置为准**，改分频只改那里。

### 4.2 帧格式

```
        ┌─SCS 低────────────────────────────────────────────┐
SCLK  ──┘  ▁▁▁ 8×3 个时钟 ▁▁▁▁ 8×N 个时钟 ▁▁▁ ──────────  └── SCS 高
MOSI  ─────┤ 地址高 ├ 地址低 ├ BSB|RWB|OM ├ 数据 … ┤
             byte0     byte1      byte2      byte3 …
MISO  ────────────（帧头期间高阻）─────────┤ 数据 ┤
```

- **地址段**：16 位偏移地址，高位在前。
- **控制段**：8 位，位域见下表。
- **数据段**：1~N 字节，偏移地址自增。

| 位 | 字段 | 含义 |
|---|---|---|
| B7~B3 | BSB[4:0] | 区域选择（选哪一块地址空间） |
| B2 | RWB | `0` = 读，`1` = 写 |
| B1~B0 | OM[1:0] | `00` 变长 / `01` 固定 1 字节 / `10` 固定 2 字节 / `11` 固定 4 字节 |

### 4.3 三条硬约束

#### ① 一次事务 = 一次 `HAL_SPI_TransmitReceive`

```c
uint8_t W5500_ReadReg8(uint16_t addr, uint8_t bsb)
{
    frame_start(addr, bsb, 0, W5500_OM_1B);   /* 填 s_tx[0..2] */
    s_tx[3] = 0xFF;
    W5500_ENABLE();                            /* SCS 拉低 */
    HAL_SPI_TransmitReceive(&hspi2, s_tx, s_rx, 4, 10);
    W5500_DISABLE();                           /* SCS 拉高 */
    return s_rx[3];
}
```

**不能拆成 `HAL_SPI_Transmit(帧头)` + `HAL_SPI_Receive(数据)` 两次调用**：
HAL 在每次调用结束时会清零 SPI 外设的 `SPE` 位、下次调用再置位，这个切换可能在 SCLK 上
多出一个边沿。W5500 依靠时钟个数解析帧，多一个边沿整帧就错位。

#### ② 单寄存器访问必须用固定长度模式（OM = 01）

变长模式下芯片靠"SCS 低电平期间有多少个时钟"判断数据长度，对毛刺零容忍；
固定长度模式下芯片只接收固定字节数，多余时钟直接丢弃。

连续读写（缓冲区传输）仍用变长模式（OM = 00），此时数据长度由实际时钟数决定。

#### ③ SCS 必须在整帧期间保持低电平

事务结束立刻拉高，否则下一帧会被拼接到上一帧后面。

### 4.4 时序预算

| 操作 | 字节数 | 耗时 @2.625MHz |
|---|---|---|
| 读一个寄存器 | 4 | ≈ 12 µs |
| 10 字节收发 | 13 | ≈ 40 µs |
| 2KB 突发 | 2051 | ≈ 6.2 ms |

> 全部为**阻塞**调用（`HAL_SPI_TransmitReceive` 忙等），会占用 CPU。见第 9 节。

## 5. 寄存器映射

### 5.1 通用寄存器（BSB = 0x00）

| 寄存器 | 地址 | 说明 |
|---|---|---|
| MR | 0x0000 | 模式；bit7 写 1 = 软件复位 |
| GAR | 0x0001 | 网关 IP，4 字节 |
| SUBR | 0x0005 | 子网掩码，4 字节 |
| SHAR | 0x0009 | MAC 地址，6 字节 |
| SIPR | 0x000F | 本机 IP，4 字节 |
| PHYCFGR | 0x002E | bit0 = LINK，bit1 = SPD(1:100M)，bit2 = DPX(1:全双工) |
| VERSIONR | 0x0039 | 芯片版本，固定 `0x04` |

### 5.2 Socket 寄存器（BSB = 4n+1）

| 寄存器 | 偏移 | 说明 |
|---|---|---|
| Sn_MR | 0x0000 | 协议：`0x01` TCP，`0x02` UDP |
| Sn_CR | 0x0001 | 命令寄存器，写入后芯片自动清零 |
| Sn_SR | 0x0003 | 状态寄存器 |
| Sn_PORT | 0x0004 | 本地端口，2 字节大端 |
| Sn_MSSR | 0x0012 | 最大报文段长度，2 字节，写 1460 |
| Sn_TX_FSR | 0x0020 | 发送缓存剩余空间（2 字节） |
| Sn_TX_WR | 0x0024 | 发送写指针（2 字节） |
| Sn_RX_RSR | 0x0026 | 已接收未读字节数（2 字节） |
| Sn_RX_RD | 0x0028 | 接收读指针（2 字节） |

### 5.3 命令码与状态值

```c
/* Sn_CR —— 写进命令寄存器。前缀必须是 W5500_CMD_，绝不能和状态值同名（见 10.2） */
#define W5500_CMD_OPEN    0x01   /* 按 Sn_MR 打开 socket          → Sn_SR = 0x13 */
#define W5500_CMD_LISTEN  0x02   /* TCP 服务器监听                → Sn_SR = 0x14 */
#define W5500_CMD_CONNECT 0x04   /* TCP 客户端连接                → Sn_SR = 0x17 */
#define W5500_CMD_DISCON  0x08   /* 断开                          → Sn_SR = 0x00 */
#define W5500_CMD_CLOSE   0x10   /* 关闭 socket                   → Sn_SR = 0x00 */
#define W5500_CMD_SEND    0x20   /* 发送缓存数据                  → 无状态变化 */
#define W5500_CMD_RECV    0x40   /* 接收完成确认                  → 无状态变化 */

/* Sn_SR —— 读状态寄存器 */
#define SOCK_CLOSED      0x00
#define SOCK_INIT        0x13
#define SOCK_LISTEN      0x14
#define SOCK_ESTABLISHED 0x17
#define SOCK_CLOSE_WAIT  0x1C
```

**注意 COSNT 语义**：`SEND` / `RECV` 不改变 `Sn_SR`，所以等待状态对它们是无效的，
只能用「等 `Sn_CR` 清零」判断完成（见 7.2 的 `cmd_only`）。

## 6. 软件架构

### 6.1 分层

```
        应用层   net_task（FreeRTOS 任务）
                    │
        服务层   W5500_Init / W5500_SetNetInfo / W5500_TcpOpen / echo_once
                    │
        命令层   sock_cmd（命令 + 校验状态） / cmd_only（命令 + 等清零） / wait_sr
                    │
        传输层   W5500_ReadReg8 / WriteReg8 / ReadBurst / WriteBurst / read16 / write16
                    │
        帧/引脚  frame_start + W5500_ENABLE / W5500_DISABLE
                    │
        硬件层   HAL_SPI（hspi2，SPI2）
```

上层不关心 SPI 细节，下层不关心 TCP 语义。

### 6.2 函数清单

| 函数 | 原型 | 说明 |
|---|---|---|
| `W5500_Init` | `void (void)` | SPI 分频、CS 拉高、写 `MR=0x80` 软件复位 |
| `W5500_SetNetInfo` | `void (void)` | 写 MAC / IP / 掩码 / 网关 |
| `W5500_TcpOpen` | `uint8_t (sn, port)` | 开 socket 并监听，0 = 成功 |
| `W5500_Net_TaskCreate` | `BaseType_t (void)` | 静态创建网络任务 |
| `W5500_ReadReg8` | `uint8_t (addr, bsb)` | 读 1 字节 |
| `W5500_WriteReg8` | `void (addr, bsb, val)` | 写 1 字节 |
| `W5500_ReadBurst` | `void (addr, bsb, buf, len)` | 连续读，`len ≤ 256` |
| `W5500_WriteBurst` | `void (addr, bsb, buf, len)` | 连续写，`len ≤ 256` |
| （内部）`frame_start` | — | 拼 3 字节帧头到 `s_tx` |
| （内部）`wait_sr` | — | 轮询 `Sn_SR` 到期望值，带超时 |
| （内部）`sock_cmd` | — | 发命令 + 校验状态迁移 |
| （内部）`cmd_only` | — | 发不影响状态的命令，等 `Sn_CR` 清零 |
| （内部）`read16`/`write16` | — | 16 位大端寄存器 |
| （内部）`echo_once` | — | 收一帧、原样回发 |

### 6.3 内存占用

| 数组 | 大小 | 用途 |
|---|---|---|
| `s_tx[3+256]` | 259 B | SPI 发送帧（帧头 + 数据） |
| `s_rx[3+256]` | 259 B | SPI 接收帧 |
| `io_buf[256]` | 256 B | 用户数据，与 SPI 帧缓冲**分开**，避免互相踩 |

任务栈 `512 words`（2KB），优先级 3，静态分配。

## 7. 关键实现

### 7.1 初始化顺序（不可调换）

```c
W5500_Init();            /* ① SPI 分频 ② CS 高 ③ MR=0x80 软件复位 ④ 等 50ms */
W5500_SetNetInfo();      /* ⑤ 写 MAC/IP/掩码/网关 —— 必须在复位之后 */
W5500_TcpOpen(0, 5000);  /* ⑥ 开 socket 并监听 */
```

**为什么必须软件复位**：W5500 的 socket 状态机**不随 MCU 复位清除**。
调试过程中反复开关 socket，很容易残留半开状态（`Sn_SR` 卡在某个值不动）。
只有 `MR=0x80` 或断电才能清干净。这也是卖家例程 `W5500_Init()` 的第一条语句。

**为什么 SetNetInfo 必须在后面**：软件复位会清空 IP/MAC 等所有配置。

### 7.2 命令与状态校验

```c
/* 有状态迁移的命令：校验 Sn_SR 是否到目标状态 */
static uint8_t sock_cmd(uint8_t sn, uint8_t cmd, uint8_t want_sr, uint16_t ms)
{
    W5500_WriteReg8(Sn_CR, W5500_BSB_SREG(sn), cmd);
    return wait_sr(sn, want_sr, ms);      /* 超时返回 1 */
}

/* 不改状态的命令（SEND / RECV）：只等 Sn_CR 清零，且必须有超时 */
static void cmd_only(uint8_t sn, uint8_t cmd)
{
    uint32_t t0;
    W5500_WriteReg8(Sn_CR, W5500_BSB_SREG(sn), cmd);
    t0 = HAL_GetTick();
    while (W5500_ReadReg8(Sn_CR, W5500_BSB_SREG(sn)) != 0)
        if ((HAL_GetTick() - t0) > 50) break;
}
```

**「`Sn_CR` 被清零」不等于「命令执行成功」**：非法命令同样会被清零。
状态能变的命令必须校验 `Sn_SR`，否则错误会被静默吞掉（这是 10.2 那次事故的核心）。

### 7.3 开监听

```c
sock_cmd(sn, W5500_CMD_CLOSE, SOCK_CLOSED, 100);  /* 先关干净，释放端口绑定 */
write16(Sn_PORT, bsb, port);                      /* 端口，大端 */
write16(Sn_MSSR, bsb, 1460);                      /* TCP 必需 */
W5500_WriteReg8(Sn_MR, bsb, 0x01);                /* 协议 = TCP */
sock_cmd(sn, W5500_CMD_OPEN,   SOCK_INIT,   100); /* → 0x13 */
sock_cmd(sn, W5500_CMD_LISTEN, SOCK_LISTEN, 100); /* → 0x14 */
```

### 7.4 状态机

| `Sn_SR` | 含义 | 处理 |
|---|---|---|
| `0x14` | LISTEN | 等待连接 |
| `0x17` | ESTABLISHED | 查 `Sn_RX_RSR`，有数据则收、处理、回发 |
| `0x1C` | CLOSE_WAIT | 对端已断，发 `DISCON` |
| `0x00` | CLOSED | 掉线，重新 `TcpOpen` |
| 其他 | 过渡态（`FIN_WAIT`/`TIME_WAIT` 等） | 当前不动，等芯片自行归位 |

> **已知缺陷**：过渡态是"干等"。如果卡在 `FIN_WAIT`/`TIME_WAIT`，会有一段时间无法连接。
> 改进方案见第 13 节。

### 7.5 接收时序

```c
len = read16(Sn_RX_RSR);                          /* ① 有多少字节 */
rd  = read16(Sn_RX_RD);                           /* ② 读指针 */
ReadBurst(rd, W5500_BSB_RXBUF(sn), io_buf, len);  /* ③ 从 RX 缓存搬出 */
write16(Sn_RX_RD, rd + len);                      /* ④ 推进读指针 */
cmd_only(sn, W5500_CMD_RECV);                     /* ⑤ 通知芯片已读走 */
```

### 7.6 发送时序

```c
if (read16(Sn_TX_FSR) < len) return;              /* ① 空间是否够 */
wr = read16(Sn_TX_WR);                            /* ② 写指针 */
WriteBurst(wr, W5500_BSB_TXBUF(sn), io_buf, len); /* ③ 数据写入 TX 缓存 */
write16(Sn_TX_WR, wr + len);                      /* ④ 推进写指针 */
cmd_only(sn, W5500_CMD_SEND);                     /* ⑤ 触发发送 */
```

**顺序不可颠倒**：必须先写数据、再推进指针。反过来会发出缓冲区里的旧内容。

## 8. 验证记录

### 8.1 链路自检

| 步骤 | 判据 | 实测 |
|---|---|---|
| SPI 通路 | `VERSIONR` == `0x04` | ✅ |
| 物理层 | `PHYCFGR` == `0xBF` | ✅ 100M 全双工，LINK UP |
| 网络层 | `ping 192.168.1.200` | ✅ 4/4，0% 丢失，TTL=128，2ms |
| 传输层 | `Sn_SR` 0x14 → 0x17 | ✅ |
| 数据 | 发 `ABCD` → 回 `ABCD` | ✅ |

### 8.2 网络参数

| 设备 | IP | 掩码 | 网关 |
|---|---|---|---|
| PC（直连时手动设） | 192.168.1.100 | 255.255.255.0 | 192.168.1.1 |
| W5500 板 | 192.168.1.200 | 255.255.255.0 | 192.168.1.1 |

- **直连**（板 ↔ PC 一根网线）：PC 必须手动设静态 IP。否则 Windows 会自配 `169.254.x.x`，不同网段必然 ping 不通。
- **经路由器**：同网段即可，PC 用 DHCP 不用改。
- 模块支持 Auto-MDIX，直连不需要交叉线。
- **ping 不需要关 Windows 防火墙**：防火墙拦的是"别人 ping 电脑"，主动发起的请求回包属于已建立会话。

## 9. RTOS 集成

### 9.1 任务参数

| 项 | 值 | 说明 |
|---|---|---|
| 创建方式 | `xTaskCreateStatic` | 与工程既有风格一致 |
| 栈 | 512 words（2KB） | `printf` 吃栈较深 |
| 优先级 | 3 | 与温湿度采集任务同级 |
| 周期 | 50ms | 轮询 `Sn_SR` |

### 9.2 阻塞行为与已知问题

`HAL_SPI_TransmitReceive` 与 `wait_sr` 里的 `HAL_Delay(1)` 都是**忙等**，
不会主动让出 CPU，只是能被 SysTick 抢占。长时间忙等会挤占同优先级任务的时间片。

**实测影响**：加入网络任务后，RS485 温湿度采集偶发 `read fail, ret=1`（Modbus 超时）。

**改进方向**：

```c
/* 把忙等换成真正的阻塞，让出 CPU */
vTaskDelay(pdMS_TO_TICKS(1));     /* 替代 HAL_Delay(1) */
```

并把网络任务优先级降到 **2**（低于温湿度任务的 3），让采集优先。

### 9.3 与其它外设的关系

| 外设 | 总线/资源 | 冲突 |
|---|---|---|
| RS485 | USART2 + DMA1_Stream5/6 | 无（不同外设） |
| W5500 | SPI2 + PE13 | 无 |
| TFT（未接） | SPI1 | 无（不同总线） |
| W25Q16（板载） | PB3/PB4/PB5 + CS=PB0 | 无（本项目不用） |

## 10. 故障档案（五个坑）

### 10.1 没共地 —— "读什么都读不到"

**现象**：`VERSIONR` 读回 `0x00`，`PHYCFGR` 是 `0x40` 这种无意义值；模块电源灯照亮；
静态量 SCS / RST 都是高电平；SPI 自环测试通过。

**原因**：模块电源不是从核心板取的时候，地没有连在一起。MCU 输出的电平对模块没有参考点。

**判据**：万用表直流档，模块 GND ↔ 核心板 GND，必须是 `0.000V`。
量模块侧数字脚若得到 **0.47V / 2.6V 这类"半高"值**，就是浮空/无共地的铁证。

**规则**：只要模块电源不是从主控板取的，**第一件事补 GND 线**，和接电源同等重要。

### 10.2 宏重名 —— LISTEN 变成非法命令

**现象**：`Sn_SR` 永远停在 `0x13`；回读 `MR/PORT/MSS/IR/RXBUF/TXBUF` 全部正常；无任何报错。

**原因**：

```c
#define SOCK_LISTEN  0x02   /* 命令 */
#define SOCK_LISTEN  0x14   /* 状态 ← 后定义者胜出，编译只给一条 warning */
```

`w5500_cmd(sn, SOCK_LISTEN)` 实际下发 `0x14`（非法命令），芯片丢弃。
而"CR 被清零"的判据对非法命令同样成立，函数返回成功。

**判据**：这条命令输出应为空。

```bash
grep -oE "define +\w+" Core/Inc/W5500.H | awk '{print $2}' | sort | uniq -d
```

**规则**：命令码 `W5500_CMD_*`，状态值 `SOCK_*`，永不同名。

### 10.3 BSB 布局与手册不同 —— "长度对、内容乱"

**现象**：TCP 能连上，发 4 字节回 4 字节，但内容全是乱码；读 RX 缓存返回 `00 00 00 00`。

**原因**：见 3.2。socket 0 的寄存器块两种算法巧合相同，只有收发缓冲区地址错位。

**判据**：连上后发 4 个字节，看从 RX 缓存读到的原始字节是否等于发送内容。

### 10.4 帧被拆成两次发送 / 用变长模式

**现象**：`Sn_CR` 写进去什么读回来就是什么；`Sn_SR` 读回 `0x81`、`0xBB` 这类不可能的状态值。

**原因**：HAL 在两次调用之间切换 `SPE`，在 SCLK 上引入额外边沿，整帧错位。

**判据**：读到物理上不存在的状态值 = 帧错位，不是芯片坏了。

### 10.5 命令判据只看 CR 清零

见 7.2。非法命令同样会清零 `Sn_CR`，必须校验 `Sn_SR` 状态迁移。

## 11. 性能与时序

| 操作 | 耗时 | 备注 |
|---|---|---|
| 读一个寄存器 | ≈12 µs | 4 字节帧 |
| 收发 10 字节 | ≈40 µs | 13 字节帧 |
| 收发 256 字节 | ≈790 µs | 259 字节帧 |
| 读 2KB 缓冲 | ≈6.2 ms | 受 `HAL_SPI_TransmitReceive` 阻塞影响 |
| 状态轮询 | 50ms 一次 | 单次 4 字节读，开销可忽略 |

**瓶颈是 SPI 频率**。若将来需要传大量数据（图像、文件），两条路：
提高分频（/8 → /4）或改用 DMA + 信号量做异步传输。

## 12. 为什么不移植 lwIP

W5500 是**全硬件 TCP/IP**，MCU 只需 SPI + socket API。上 lwIP 只有一条路：
Socket0 设成 MACRAW 模式，W5500 退化成 MAC+PHY，协议栈搬回 STM32 跑。

| 对比项 | 硬件栈（本项目） | lwIP over MACRAW |
|---|---|---|
| 可用 socket | 8 个 | 1 个（MACRAW 只支持 Socket0） |
| Flash | ~10KB 驱动 | +40~60KB |
| RAM | ~2KB | +16~32KB |
| CPU | 近似 0 | 每包拷贝 + 校验和 |
| 开发量 | 1 天 | 3~5 天（netif 驱动 + `sys_arch` 移植） |

**另一个常见误区**：CubeMX 里勾选 LwIP 对 W5500 **完全无效**。
它生成的 `ethernetif.c` 操作的是 STM32 片上 ETH 的 DMA 描述符，对接 LAN8720 这类 PHY，
与 SPI 外接的 W5500 没有任何关系。

## 附录 A：五分钟排查 checklist

设备连不上时，按顺序走，每一步都有明确判据：

1. **`VERSIONR` 是不是 `0x04`？**
   不是 → SPI 通路问题：查共地（10.1）、SCS 是否拉到模块、MISO/MOSI 是否接反。
   读到 `0x00` = MISO 恒低；`0xFF` = MISO 恒高（CS 没拉低或 RST 被拉低）。
2. **`PHYCFGR` 的 bit0 是不是 1？**
   不是 → 网线没插、对端没通电、或模块供电不足。
3. **`ping` 通不通？**
   不通 → IP/掩码不同网段（PC 是不是 169.254.x.x？）、PC 网卡选错、IP 冲突。
4. **`Sn_SR` 停在哪个值？**
   - 停在 `0x13` → LISTEN 没生效：查命令码是否撞名（10.2）、MSSR/PORT 是否写进去。
   - 停在 `0x00` → OPEN 失败：查 `Sn_MR` 是否为 TCP。
5. **能连上但数据乱？**
   发 4 个已知字节，看 RX 缓存读到的原始值：全 0 或随机 = BSB 布局不对（10.3）。
6. **`Sn_CR` 读回刚写入的值？**
   → 命令没被执行：查帧是否被拆成两次发送（10.4）、OM 是否用了变长模式。
